# Action Trigger 原则 & System/User 分层（2026-04-22 翻车复盘）

## 血泪教训

在实验中遇到："优化后的 Prompt"**不产出结果**，反而回复 "我已准备就绪，请开始向我提问吧"。

**根因**：Prompt 是 System 形态却以 User message 发送 → 模型进入"待命模式"而非"执行模式"。

## 三条铁律

### 铁律 1：System/User 分层

| 放 System | 放 User |
|---|---|
| 角色定义 | 当下具体任务 |
| 规则/约束/禁忌 | 具体输入参数 |
| Few-shot 示例 | Action Trigger |

**never** 把所有东西塞一个 user message。

### 铁律 2：Action Trigger 不可省

每个 User message 必须**以一句明确的"立即开始"结尾**：

推荐模板：
> "立即输出 [内容]，不要做任何解释或确认，直接从 [起点] 开始。"

### 铁律 3：禁忌条款 > 鼓励条款

- "请注意专业" ❌（模糊）
- "不使用'我们很遗憾'；不编造姓名邮箱，用[占位符]代替" ✅（可执行）

## 数据对比

| Prompt 形态 | 是否产出 |
|---|---|
| 原版（粗糙单消息） | ✅ 产出（质量 70 分） |
| 华丽优化版（单消息） | ❌ 不产出（0 分） |
| System/User 分层 + Action Trigger | ✅ 产出（95 分） |

## 修正说明（2026-04-22 晚）

### 翻车的真正原因（数据修正）

初次诊断：认为"过度工程化 Prompt → 模型待命"
真正原因：**占位符 `<把 DeepSeek 给你的整个优化 Prompt 粘这里>` 未清理**，模型误判为"用户还没说完"

### 新增原则：Few-shot 防"照抄"

真实测试发现：DeepSeek 自写的优化 Prompt **能产出邮件**，但会把 example 里的
具体姓名（李工）、公司（ABC科技）、数字（7天）复制到真实输出。

**解决方案**：
1. Example 里具体信息全部用 [占位符]
2. System Prompt 明确禁止："禁止复用 example 中的具体姓名、日期、公司名"
3. 或拆分 example → "结构示例（无具体信息）" + "内容指南（说明风格）"
